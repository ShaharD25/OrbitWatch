# OrbitWatch

מנוע C++20 לניתוח קרבה בין מסלולים דגומים, עם ממשק Qt 6 דו־ממדי.

## מצב הגרסה

הליבה נבנתה ונבדקה ב־Ubuntu 26.04 / WSL2, GCC 15.2 ו־CMake 4.2.3.
Qt 6 הותקן וכל היעדים נבנו בהצלחה ב־Release. בדיקות הליבה, JSON וזרימת GUI
ללא תצוגה עברו. נבדקו גם CLI מקצה לקצה עם 100 ו־500 אובייקטים, ויצירת תרחיש
500×1000. פתיחה קצרה בתצוגת WSLg הסתיימה בהצלחה.
עדיין נדרשת סקירה חזותית ידנית; בדיקות פתיחה אינן אישור לאיכות הציור או לקצב הפריימים.

## התקנה ובנייה

במסוף Ubuntu/WSL2:

```bash
sudo apt-get install -y qt6-base-dev qt6-quick3d-dev qt6-declarative-dev qml6-module-qtquick3d qml6-module-qtquick qml6-module-qtqml-workerscript
cmake -S . -B build-gui -DCMAKE_BUILD_TYPE=Release
cmake --build build-gui -j 2
ctest --test-dir build-gui --output-on-failure
./build-gui/orbitwatch
```

אם החבילה אינה נמצאת, יש לרענן את רשימת החבילות באמצעות `sudo apt-get update`.
GUI דורש סביבת תצוגה פעילה כגון WSLg. בדיקת smoke אוטומטית משתמשת ב־offscreen;
היא אינה מחליפה בדיקה ידנית של חלון, ציור, ניגון ובחירת אירועים.
אין תלות ב־GoogleTest או בספריית JSON נוספת: בדיקות הליבה הן executable עצמאי
ו־JSON מטופל ב־Qt Core, מחוץ למנוע החישובים.

## שימוש

האפליקציה נפתחת עם 100 אובייקטים. כפתור Demo טוען 500.
בחרי סף במטרים ולחצי Analyze. בחרי אירוע בטבלה כדי להגיע לדגימת המינימום.
אפשר לבחור היטל XY/XZ/YZ, לנגן דגימות ולייצא JSON או CSV.
סמנים אדומים ונתיבים מציינים את הזוג באירוע הנבחר, גם כשמנווטים לזמן אחר.
שינוי הסף מבטל את עדכניות התוצאות. החישוב רץ ברקע וניתן לביטול.

```bash
./build-gui/orbitwatch_cli examples/demo-100.json 10000 report.json
./build-gui/orbitwatch_cli examples/demo-500.json 10000 report.csv
./build-gui/orbitwatch_cli --generate 500 1000 /tmp/demo-500.json
python3 tools/generate_examples.py --objects 500 --samples 1000 --output /tmp/demo-python.json
```

קודי יציאה: 0 הצלחה, 1 שגיאת נתונים/הרצה, 2 שימוש שגוי ב־CLI.
אין לדרוס את קובץ המקור באמצעות נתיב הדוח.

## בנייה ובדיקות ללא Qt

```bash
cmake -S . -B build-core -DORBITWATCH_BUILD_GUI=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build-core -j 2
ctest --test-dir build-core --output-on-failure
./build-core/orbitwatch_benchmark
```

בדיקות Sanitizers:

```bash
cmake -S . -B build-sanitize -DORBITWATCH_BUILD_GUI=OFF -DORBITWATCH_SANITIZERS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-sanitize -j 2
ctest --test-dir build-sanitize --output-on-failure
```

## חוזה נתונים

קובץ JSON מכיל `schema_version: 1`, `units: "m"`, `time_unit: "us"`,
`frame: "SCENARIO_CARTESIAN"`, שם, `times_us` ורשימת `objects`.
לכל אובייקט `id` ייחודי ומערך `positions` של שלשות `[x,y,z]`.
הזמנים משותפים לכל האובייקטים, מתחילים באפס ועולים ממש. זמן הוא מספר שלם
של מיקרו־שניות מתחילת תרחיש, ללא משמעות UTC. בקובץ הוא מוגבל ל־2^53-1.
מערכת הצירים קרטזית ימנית; אין המרות מערכות ייחוס. התצוגה בקילומטרים,
והחישובים בתלת־ממד ובמטרים.

מגבלות: 2–500 אובייקטים, 2–10,000 דגימות, קובץ עד 256 MiB,
קואורדינטות סופיות בטווח ±10^12 מטר, ועד 100,000 אירועים להרצה.
חריגה ממגבלת אירועים מכשילה את ההרצה, ללא פלט חלקי מוצלח.
מגבלות הקובץ והדגימות אינן הבטחת צריכת זיכרון לכל קלט אפשרי.

## הגדרת אירוע

אירוע הוא רצף מרבי של דגימות שבהן המרחק האוקלידי התלת־ממדי קטן או שווה לסף.
דגימה בודדת מספיקה; דגימה מעל הסף מפצלת אירועים. בשוויון מינימום נבחר הזמן
המוקדם ביותר. זמני תחילה וסוף הם זמני דגימה, לא זמני חציית סף מחושבים.
המינימום הוא מינימום מדוגם: אירועים בין דגימות עשויים שלא להתגלות.
קרבה גאומטרית אינה הסתברות להתנגשות. הנתונים סינתטיים, לא תוצר מודל מסלולי.
לזוג OBJ-1/OBJ-2 בתרחישי הדוגמה מינימום של 100 מטר בדגימה האמצעית.

## ארכיטקטורה

- `orbitwatch_core`: מודל, אימות, מרחקים, אירועים ומחולל תרחיש; ללא Qt.
- `orbitwatch_io`: JSON, CSV וכתיבה אטומית באמצעות Qt Core.
- `orbitwatch_gui`: Qt Widgets, היטל 2D וחישוב ברקע באמצעות Qt Concurrent.
- `orbitwatch`: נקודת כניסה לאפליקציה הגרפית.
- `orbitwatch_cli`: אותה ליבה ואותה שכבת קלט/פלט ללא חלון.
- `tests`: מקרי ייחוס, שגיאות, תכונות, ביטול וביצועים; בדיקות I/O ו־GUI כש־Qt זמין.

עלות האלגוריתם O(T·N²). הוא מעבד זוג בכל פעם ושומר רק אירוע פעיל ותוצאות,
ללא מטריצת כל המרחקים: זיכרון O(N·T + E). בחירה זו מפשטת את המימוש הסדרתי.
התחלה/סיום/מינימום נשמרים כאינדקסים לרשת הזמן המשותפת.

## אימות ומגבלות נוכחיות

במדידת Release יחידה: 100×1000 כ־0.011 שניות, 250×1000 כ־0.072 שניות,
500×1000 כ־0.318 שניות. אלו זמני מנוע בלבד, ללא I/O וציור, ולא Benchmark מייצג
לכל מחשב או נתונים. מטריצת המדידות ניתנת להרצה ב־orbitwatch_benchmark.
בדיקות הליבה עברו גם עם AddressSanitizer, UndefinedBehaviorSanitizer ו־LeakSanitizer.
LeakSanitizer דרש הרצה מחוץ לארגז החול עקב מגבלת ptrace; ההרצה המלאה עברה.
קובצי הדוגמה נבדקו גם ב־Python: גדלים, מזהים ומינימום ידוע של 100 מטר.
בבדיקת WSLg עם 500 אובייקטים ו־1,000 דגימות נמדד שיא RSS של כ־75.3 MiB.
ב־100 עדכוני דגימה עם נתיבי הזוג הנבחר: חציון update+repaint כ־3.73 ms,
אחוזון 95 כ־30.44 ms. זו מדידה מקומית של עדכון וציור, לא מדידת FPS בתצוגה.
בדיקת ביטול דרך GUI עברה, כולל סגירה לאחר ביטול; תוקנה חריגה שיצאה מה־destructor.
יעד 30 FPS וביטול בתוך שנייה עדיין דורשים מדידה ייעודית.

בדיקת GUI אוטומטית מפעילה 500 אובייקטים, ממתינה לניתוח ברקע, מאמתת מינימום
של 100 מטר, בוחרת אירוע ומוודאת ניווט לדגימה 500, החלפת היטל וביטול עדכניות
לאחר שינוי סף. אם Python זמין, CTest מריץ גם בדיקת CLI מקצה לקצה.
השלמות שנותרו: סקירה חזותית ב־WSLg, מדידות FPS ותגובתיות נוספות
ואוטומציית CI לאחר בחירת שירות.
לא הוגדר שירות חיצוני ולא פורסם קוד.


## כדור הארץ בתלת־ממד — שלב ראשון

בבנייה הרגילה נפתחת לשונית **Earth · 3D**: כדור ארץ עם תמונת NASA מקומית הכוללת עננים,
תאורה, שוליים אטמוספריים עדינים ורקע כמעט שחור. גרירה בלחצן השמאלי מסובבת את
המצלמה סביב הכדור, גלגלת מקרבת ומרחיקה, ולחיצה כפולה או Reset view מאפסות.
לשונית **Analysis · 2D** שומרת את יכולות הניתוח וההמחשה הקודמות.
אין עדיין לוויינים, מסלולים או סימון אירועים בתצוגת התלת־ממד.

`EarthView` הוא רכיב תצוגה עצמאי; `qml/Earth.qml` מגדיר את הסצנה והשליטה,
ושני קובצי atmosphere מגדירים הילה חזותית בלבד. אין כאן מודל אטמוספרי,
מודל סיבוב כדור הארץ או התאמה לזמן התרחיש. הגלובוס ממורכז בראשית התצוגה;
נתוני התרחישים והמנוע לא שונו. שינוי המצלמה אינו משנה את הנתונים המדעיים.
כל הנכסים ארוזים במשאבי Qt, ולכן התצוגה אינה דורשת רשת או תיקיית עבודה מסוימת.

נדרש backend גרפי תלת־ממדי פעיל (למשל OpenGL דרך WSLg/Mesa).
מצב Qt Quick software הדו־ממדי אינו יכול לצייר Qt Quick 3D. בדיקת
`earth_controls` ב־CTest בודקת טעינה ושליטה ללא מסך, ואינה הוכחת ציור 3D.
לבדיקת ציור ושליטה אמיתית ב־WSLg:

```bash
./build-gui/orbitwatch_earth_tests --render-check --integrated
```

אפשר לשמור צילום מקומי באמצעות משתנה הסביבה ORBITWATCH_SCREENSHOT.
למחשב ללא תמיכת 3D ניתן לבנות את הממשק הקודם באמצעות
`-DORBITWATCH_BUILD_3D=OFF`. בניית הליבה ללא GUI נשארת זמינה כרגיל.

אימות השלב הראשון: כל שש בדיקות CTest עברו. בנוסף הורץ
`orbitwatch_earth_tests --render-check --integrated` ב־WSLg: טעינת הסצנה,
ציור פני השטח, שינוי תמונה בעקבות גרירה, Zoom פנימה והחוצה, גבולות Zoom
ואיפוס עברו. צילום החלון המשולב נבדק חזותית. המנוע וקובצי הדוגמה אומתו

עדכון חזותי: הוסרו הכוכבים הדקורטיביים והאור הכחול בצד החשוך; אור שמש לבן

## פריסת סביבת העבודה

החלון מסודר בשלוש עמודות: טעינת JSON, תרחישי Demo (100/500), סף קרבה
ורשימת האובייקטים משמאל; גלובוס/ניתוח דו־ממדי וציר זמן במרכז; אירועים,
פרטי האירוע וייצוא JSON/CSV מימין. החיפוש בחלק העליון מסנן את רשימת
האובייקטים הטעונים בלבד. הוא אינו מצייר או מסתיר לוויינים בתלת־ממד.

ניתוח אינו מחליף את הלשונית הפעילה. בחירת אירוע מציגה את המרחק, זמני הדגימה
ומיקומי שני האובייקטים בדגימת המינימום. הכפתור View event in 2D מציג את
הזוג בהמחשה הקיימת. רשימת האירועים והמספרים הם תוצאות מנוע אמיתיות;
אין אירועים או מדדי ביצועים קבועים שנועדו למלא את העיצוב.

הגלובוס משלב תמונת יום וקומפוזיט אורות ערים של NASA/NOAA בצד הלילה,
עם תאורה חלשה שמאפשרת לראות את פני השטח גם בחושך. אלו נכסים היסטוריים
עם תאורה להמחשה; ציר הזמן עדיין שולט במסלולי התרחיש בלבד ולא בגלובוס.
תנאי השימוש והקרדיטים נמצאים ב־THIRD_PARTY_NOTICES.md.
לוויינים, מסלולים וסימון אירועים בתלת־ממד טרם נוספו.

לבדיקת החלון עם ניתוח דוגמה אמיתי וצילום מקומי אופציונלי:

```bash
ORBITWATCH_SCREENSHOT=/tmp/orbitwatch-dashboard.png ./build-gui/orbitwatch_earth_tests --render-check --integrated --with-analysis
```
